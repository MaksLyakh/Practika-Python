# Дополнительные исследования

## Где хранятся данные

- SQLite: пациенты, врачи, отделения, записи, цены и связи между сущностями. Нужна целостность и транзакции.
- Redis: временный кэш свободных слотов врача. TTL 60 секунд, после записи - инвалидирование.
- MongoDB: эксперимент с документом расписания врача (массив часов).
- CDN: публичные фотографии и картинки, не персональные медицинские данные.

## Redis: два экземпляра API

```
API 5000 --+
           +--> Redis 6379
API 5002 --+
```

Общий ключ `slots:1:2026-12-10` виден обоим экземплярам. Redis не заменяет основную SQL-БД.

## Репликация (теория)

```
Основная БД --> Реплика для чтения
      |
      +--> резервная копия
```

Плюсы: отказоустойчивость и распределение запросов. Минусы: задержка репликации, усложнение настройки, возможная временная несогласованность. Настоящая репликация в проекте не развёрнута.

## CDN

Отдельный локальный сервер на порту 5001 имитирует раздачу статического содержимого с кэшированием. Для реального CDN нужен внешний провайдер. Наличие Cache-Control само по себе не доказывает, что ресурс уже находится в кэше CDN.

## Индексы

`idx_appointments_doctor_time` ускоряет выборку расписания врача. `idx_appointments_patient` помогает находить записи пациента. `idx_doctors_specialty` помогает фильтровать врачей по специализации. Индексы занимают место и замедляют изменения, поэтому создавать их на каждом поле не следует.

## Транзакция

`book_with_patient` создаёт пациента (если ещё не существует) и запись на приём в одной транзакции. При ошибке второго INSERT первый откатывается.
